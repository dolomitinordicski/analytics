## Migration protocol

1. **Freeze baseline**
   - Do not alter current production datasets.
   - Keep current compatibility dataset and source HTML fingerprint.

2. **Inventory 100%**
   - Every numeric literal used by a rendered chart/table/KPI is assigned an ID.
   - Every ID gets: source file, source field, season, scope, unit, target Firestore document, transformation rule.
   - No unmapped numeric value may proceed to migration.

3. **Copy to DNS_Core**
   - Write canonical historical records without changing Analytics reads.
   - Preserve exact decimal precision and original labels/source metadata.
   - Never overwrite an existing canonical record without explicit parity proof.

4. **Read in parallel**
   - Load canonical data and compatibility data simultaneously.
   - Compute field-by-field parity before rendering live data.

5. **Exact parity gate**
   - Integers: exact equality.
   - Currency totals: exact cents.
   - Decimal kilometre/KP values: exact source precision before display rounding.
   - Arrays: same length, ordering, labels and values.
   - Editorial text: unchanged except explicitly documented verified-source annotations.
   - 0 mismatches required.

6. **UI parity**
   - Same number of sections, cards, charts, tables and insights.
   - Same labels and bilingual content.
   - No chart or table disappears when switching source.

7. **Switch**
   - Only datasets with 100% parity switch to canonical source.
   - Any mismatch keeps the compatibility source active and visible in diagnostics.

8. **Remove runtime hardcoding last**
   - Hardcoded operational values leave runtime only after all parity checks pass.
   - The frozen audit/source snapshot remains in the repository as historical evidence, so nothing is actually lost.

## Acceptance criteria

A.3.11 is complete only when:
- all operational/historical rendered values are canonical-source driven;
- compatibility fallback reports zero operational use in normal production;
- parity checks report zero mismatches across all modules;
- PR #30 content-preservation checks still pass;
- the six legacy pages and the additional Intensity module remain complete;
- no editorial or methodological content has been removed.

Until then, the correct status is **migration in progress**, not “zero hardcoded data”.
